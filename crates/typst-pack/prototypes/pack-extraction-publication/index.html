Throwaway logic prototype · issue “Prototype Pack extraction and publication”

Plan semantics first. Publish bytes second.

This demo tests whether one lifecycle shape remains truthful across two very different destinations: a filesystem can stage and commit a new tree, while object storage generally exposes deterministic partial progress.

Question: Can featureless, owned, canonical plans keep Pack Extraction and Compilation Output Artifact semantics out of destination adapters without hiding conflict policy, partial writes, retry behavior, or payload ownership?

Guided walkthroughs

Collision never reaches storage

A project file named packages conflicts with package descendants. The semantic planner rejects it without consulting a destination.

Filesystem all-or-nothing

An absent-root publication stages all entries. A late failure removes the private stage and leaves no visible destination tree.

Object-store replay

Create-or-verify reports completed keys and an indeterminate failed write. Replaying compares exact bytes and safely finishes the plan.

Decisions this candidate makes visible

  • Two semantic plan types, not one public generic byte-plan. They preserve Pack Identity or Compilation Result Identity and expose only their own role vocabulary. Concrete adapters privately share iteration machinery.
  • Plans own shared immutable payload handles. Cloning a plan never copies payload bytes, OpenDAL requests own a cheap clone, and the original plan remains available for explicit replay.
  • Filesystem policy stays filesystem-specific. Merge/create, merge/replace, and absent-root atomic publication are materially different promises and are not squeezed into OpenDAL’s create-or-verify and replace-exact-keys policies.
  • Filesystem preflight is complete and commits are atomic per file. Known platform, topology, policy, and confinement failures precede writes. A merge may publish a partial set, but never a truncated planned file.
  • Workflow-specific receipts describe storage facts. Failures retain committed files, created directories, residual staging state, and the failed phase without mutating the Pack, plan, or Compilation Result.
