Decisions visible in this candidate

  • One external seam. Request acceptance, exact fulfillment verification, private World materialization, compilation, and export are implementation stages, not caller-orchestrated modules.
  • Validated dependency values. Fulfillments carry independently canonical PackageTree and FontContainer values. Compilation verifies Pack correspondence and identities, not raw syntax.
  • A set is already unique. CompilationFulfillmentSet rejects duplicate package specifications and Font Container identities during construction; duplicate claims never become a Pack Compilation Request.
  • Semantic rejection wins. Invalid controls return one complete CompilationRequestRejection before fulfillment values are inspected or a CompilationIdentity exists.
  • Accepted operational failure remains reportable. Missing, unexpected, embedded, and identity-mismatched fulfillments are aggregated in canonical order inside a CompilationOperationOutcome. Malformed raw bytes fail before compilation while constructing the validated dependency value.
  • Compiler rejection is a result. It owns diagnostics, trace, summary, and a result identity but no artifacts. It is not a Rust error or an operational outcome.
  • Publication starts later. Only a succeeded CompilationResult can become a CompilationArtifactPublicationPlan; destinations and storage outcomes never enter compilation.
  • Deferred: exact borrowing, allocation sharing, copy behavior, peak memory, and numeric ceilings belong to the lifecycle ownership and limits decision.
