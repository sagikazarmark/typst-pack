Package and font creation inputs

Can a small set of validated values support eager input checks, ordered font selection, and stateless package discovery without exposing acquisition machinery to Pack Creation?

Current state

Free play

Pack Assembly changes catalogs between calls. create only borrows the values for one synchronous Dependency Discovery run.

Event log

    Guided walkthroughs

    Recommended decisions

    Validate before Pack CreationPackageTree, PackageCatalog, FontContainer, and DiscoverySpecification establish their own local invariants. Whole-Pack invariants still belong to the private Pack construction seam.
    Treat duplicate font bytes as distinct positionsFont Catalog position remains semantic. Identical bytes may carry different dispositions; the first selected position decides the requirement.
    Keep authorities out of the shared core interfaceConcrete filesystem and host workflows own acquisition. Add a shared authority trait only after two production workflows demonstrate the same contract.
    Carry stable failures separatelyA typst-pack-owned reason preserves absent-package, absent-version, network, malformed-archive, and other cases without exposing the compiler type. A Package Tree wins over an older failure; otherwise the private engine adapter attaches it to the importing source request.
    Resume by mutating one validated catalogPackageCatalog::try_insert verifies each new exact specification and tree. Each synchronous create call only borrows the current catalog, so no large resource value is rebuilt merely to cross an await point.

    Questions this prototype exposes

    1. Run “Nested resumption”: does the borrowed invocation make the stateless resume loop clear without introducing a continuation or session?
    2. Run “Failure attachment”: does the stable failure reason preserve enough information at the importing source?
    3. Run “Font positions”: does identity equality remaining separate from disposition match the intended model?
